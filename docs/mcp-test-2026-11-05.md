## Findings

1. (#88) **`create_category` does not refuse a duplicate name.** The second call with name
   `Testkat A` in the same group created `mcp_test.testkat_a_2` instead of failing. The tool
   description says to check `list_categories` first, so this is by design, but an agent that
   skips the check will create duplicates, and the name is then ambiguous for
   `rename_category`.
2. (#89) **`copy_last_month` can push Ready to Assign far below zero.** On 2026-11 it copied 46
   categories and Ready to Assign went from 451.77 to -5988.23 with no warning in the result.
   It is the same arithmetic as in the app, but the result message does not say so.
3. (#90) **A rule on `merchant` never matches a manual booking.** `mcp_test_rule`
   (`merchant: (?i)mcp testkiosk`, `purpose: mcp test`) showed 0 matches although booking
   8666 had payee `MCP Testkiosk` and that purpose. Manual bookings have `merchant: null`
   (see `get_booking 8667`); rules on `counterparty` would match. `test_rule` has the same
   behaviour, so it reports it correctly.
4. (#91) **`test_rule` sample paging:** `matching` was 410 for `rewe`, but the `samples` block says
   `total: 10`, which is the number of samples returned, not the match count. Easy to misread.
5. (#92) **`accept_suggestions` accepts a rule-categorized booking.** Booking 8655 had source
   `rule`, not an ML suggestion, and the call still answered `1 suggestions accepted`.
   `list_bookings category=review` was empty at the time, so there was nothing to review.
6. (#93) **One-sided transfer after categorizing.** Booking 8646 (ING Girokonto, -150.00, transfer
   to Revolut) could be set to `lebensmittel.drogerie`. Its Revolut partner 8662 (+150.00) stayed
   `transfer: ING Girokonto` (`counterpart_of: null`, both are imported bookings), so the pair
   no longer cancels out until 8646 is reset. `reset_bookings` brought it back.
7. (#94) **`get_overview` `upcoming`** lists payments dated 2026-10-30 and 2026-10-31 although today
   is 2026-11-05 (overdue expected payments). Possibly intended; it is not labelled as overdue.

None of these is a crash.
